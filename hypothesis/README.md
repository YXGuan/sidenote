# Hypothesis with local research features

This is the **actual Hypothesis client and browser extension**, with their original
interface, styling, assets, annotation cards, editor, and groups.
Requested features are integrated into those repositories. There is no separate
reading app or companion popup.

**New checkout?** Start with [the first-run setup guide](../docs/SETUP.md) or give
your local coding agent [the copy-paste setup prompt](../README.md#clone-and-hand-setup-to-your-agent).
`browser-extension/build/` is generated by setup; it is not included in a clone.
For source changes and checks, use [the development guide](../docs/DEVELOPMENT.md).

## Use the finished build

The loadable extension is in [`browser-extension/build/`](browser-extension/build/).
Its Chrome name is **sidenote**, with its own stable extension ID:
`lebpfahhlannplfhlllolppkmcapecge`. It can be installed alongside the official
Hypothesis extension (`bjfhmglciegochdpefhhlphglcehbmek`) in the same Chrome
profile. Its public manifest key is separate from the official key, so rebuilding
or moving this checkout preserves its independent identity.

If you loaded the earlier build that replaced the official extension:

1. In `chrome://extensions`, remove the old unpacked entry loaded from this repo.
2. Restore the [official extension from the Chrome Web Store](https://chromewebstore.google.com/detail/hypothesis-web-pdf-annota/bjfhmglciegochdpefhhlphglcehbmek) if it is missing.
3. Use **Load unpacked** to load `browser-extension/build/` again. It now appears
   separately as **sidenote**.

Use one extension's toolbar button per page; reload the page before switching
between the two clients.

Pair the extension with the local backend **once per browser profile**. Open its
normal **Extension options** page. Under **Local research**, enter and save the
key printed by this command, run from the repository root:

```sh
./research-partner/notes pair
```

This command is still current. `research-partner/` contains the backend and notes
vault, not a separate interface. The local key is different from your Hypothesis
login or developer API token. Skip pairing if this browser profile is already
paired; the saved key survives browser and backend restarts. Pair again only for
a new profile or if the saved extension settings or backend key are reset.

After initializing your account/vault and installing local dependencies through
setup, install the local storage service once on macOS:

```sh
./research-partner/notes service --install
./research-partner/notes service --status
```

It starts at login and restarts automatically after exits. A terminal does not
need to stay open. The original `notes serve` command remains available for
foreground debugging after stopping the background service. See the
[service guide](../research-partner/README.md#local-service).

In the local sidebar, the original **Log in** control connects the Hypothesis
account configured in the paired backend. The official extension continues using
its normal OAuth login. A distinct extension ID cannot use the official client's
registered login origin; the local build uses your configured developer token
instead. Run `./research-partner/notes configure` if an account is not configured.
The backend must be running when a new sidebar retrieves its account token.
**Log out** disconnects only the local sidebar; it does not revoke the backend
token or log out the official extension.

Then use Hypothesis as usual:

- **Show annotations → Only mine / Everyone**, at the top of the browser sidebar,
  controls both annotation cards and highlights in the page. sidenote
  defaults to **Only mine** and remembers your choice across reloads and group
  changes. Creating or saving an annotation keeps this filter active. **Everyone**
  restores the current group's annotations; the filter never deletes saved data
  or changes annotation sharing permissions. When signed out, Only mine shows a
  login hint and hides other authors until you choose Everyone.
- **Page Notes → Page details** holds the URL's personal title, observed authors,
  institutions, journal, DOI, separate manual and auto tag fields, automatic type/topic/subtopic groups,
  manual collections, and Like/Dislike page reactions. Citation fields and classification are editable; page activity shows first-added/modified timestamps and recorded visits.
  Manual tags and automatic tags are stored separately and do not edit
  annotation drafts. Unknown citation fields remain unavailable.
- Each saved annotation has its own like/dislike controls and **Annotation
  sentiment → Analyze this annotation**. The analysis uses only that annotation;
  a highlight alone is not treated as agreement. Explicit reactions and inferred
  sentiment are stored separately.
- **User menu → Local library** opens the dashboard inside this same original
  client. It offers Studio, Paper, Compact (the default), and Classic (the previous
  month-grouped layout), each with Library, Dashboard, and Collections tabs.
  Clickable charts count annotations by topic, subtopic, and source authors, with
  saved-page counts also available. Collections include local NLP-based Liked (Auto)
  and Questions (Auto), plus Visit Often (3 visits in 30 days). Saved-page loads and
  tab returns are tracked without opening the sidebar; earlier counts are sidebar
  captures. It includes full-text search, removable filter
  chips, and date/metadata filters. See the
  [view guide](DASHBOARD.md). It also has a
  **Back up now** control. The same dashboard opens from **Extension options →
  Open local library**.
- On your hosted Hypothesis profile, the existing inline
  pencil still edits the URL's local personal title and restores it on reload.
- Opening the sidebar captures citation metadata through Hypothesis's original
  frame/metadata pipeline. Publishing an annotation uses the real Hypothesis API
  and mirrors the successful save locally. Daily sync independently backs up
  annotations created from either extension or other clients.

The dashboard's stable address is:

```text
chrome-extension://lebpfahhlannplfhlllolppkmcapecge/client/notebook.html?local-library=1
```

**Cloud versus local:** Clicking **Post to…** saves the annotation to your actual
Hypothesis account with the chosen sharing setting. Personal page titles, page
metadata/tags, annotation reactions, and inferred sentiment stay in the local
vault; those extra fields are not added to hosted annotation records. Drafts are
not published until you use the original Post control.

The Hypothesis account token is stored only in the backend's ignored `research-partner/.env` (mode 600) and
passed over the paired loopback connection into the extension sidebar's memory
when needed. It is never baked into the extension, saved in Chrome storage, or
returned to a website's content script. The extension saves its local pairing key
and a login preference. Categorization uses offline local rules by default and runs after imports and
captures. Optional headless Codex calls use GPT-6 Luna with low reasoning effort.
The [classification guide](../research-partner/docs/CLASSIFICATION.md) explains
provider choices, model setup, and local NLP alternatives. Automatic page
refreshes can be disabled in the same extension options page. A missing local
service does not prevent normal Hypothesis reading, annotation, or saving.

## Rebuild

```sh
./hypothesis/build
```

The script reconstructs missing checkouts at the recorded commits, applies the
patches, installs locked dependencies when needed, builds the client, then builds
the extension using its original Makefile. It does not reset existing work.

After each rebuild, open `chrome://extensions/?id=lebpfahhlannplfhlllolppkmcapecge`
and click **Reload** for **sidenote**, then refresh the dashboard/source
tabs. This reloads its background worker as well as the client files. No new
pairing is needed. A worker from an earlier build can reject newer dashboard
requests; the dashboard now keeps saved pages visible if optional information
is unavailable and provides a Retry connection control.

After making native source changes, refresh the tracked patches:

```sh
./hypothesis/build --export-patches
```

Native changes extend the existing metadata pipeline, annotation action
bar, Page Notes, local library, document header, post-save mirroring, account service, extension
identity/background worker, existing options page, and a profile content script. Global Hypothesis styling
and layouts are preserved.

## Your data

The default vault is `research-partner/vault/`; setup creates it locally. A new
clone contains no personal notes, imports, credentials or daily sync jobs.
Use `./research-partner/notes doctor --json` for the actual state of your install.
See [setup](../docs/SETUP.md#optional-account-and-data-setup) to import annotations
or opt into a daily sync. Existing vaults and pairing are preserved on rebuilds.

See the [PRD](../research-partner/docs/PRD.md) for search/chat, evolving wiki pages,
recommendations, collaboration, and monetization hypotheses. Personal titles and
reactions remain local; the original hosted annotation records and sharing
permissions keep their normal Hypothesis behavior.

## Verify

```sh
cd hypothesis/client
node .yarn/releases/yarn-3.6.0.cjs typecheck
node .yarn/releases/yarn-3.6.0.cjs test --grep 'AnnotationActionBar|AnnotationEditor|AnnotationHeader|TagEditor|LocalResearchActions|PageResearch|SidebarTabs|HypothesisApp|UserMenu|html-metadata-test|services/test/annotations-test|services/test/auth-test|frame-sync-test'

cd ../browser-extension
node .yarn/releases/yarn-3.6.1.cjs typecheck
node .yarn/releases/yarn-3.6.1.cjs test
```

From the sidenote repo root, `python3 -B hypothesis/test-native.py` loads the
actual built extension in an isolated Chromium profile and uses a temporary
knowledge vault. Publisher/API responses and AI tag proposals use synthetic test
fixtures; the original client rendering, extension worker, and local HTTP bridge
are real. Set `HYPOTHESIS_CHROMIUM_PATH` when Chromium is installed outside the
default macOS Playwright cache.
Set `HYPOTHESIS_OFFICIAL_EXTENSION` to an installed official extension's version
directory to verify both real extensions load in the same isolated profile. The
test copies only that extension's package files and does not change your Chrome
profile.
